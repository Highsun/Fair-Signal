# 算法与框架检查、改进对照实验

## 检查发现

原实现的奖励符号、标准 DQN 更新、时间截断 bootstrap、黄灯/全红计时、
最小和最大绿灯执行、全程等待统计与验证/测试划分没有发现颠倒或未执行的问题。
现有真实 SUMO 测试覆盖约束、失败策略删失、全程等待、参数更新与保存/重载。
但是以下建模限制与目标差异值得处理：

1. 原公平奖励只对停车队首超过 90 秒的部分收费。队后有更老的车辆时会漏记；
   90 秒以下没有公平梯度，而本轮验证 P95 大多低于 90 秒。优化超 90 秒比例
   不等于优化 P95。此前单训练种子的 P95/效率结果也不足以判定稳定的算法排名。
2. 原过渡观测只给目标相位、过渡布尔标记与阶段计时；黄灯与全红可能得到相同观测，
   不同的原相位也可能相同。180 秒以上等待被裁剪为同一个数值。
   这是明确的观测混叠；并不等于证明它是之前性能差异的主因。
3. 最小绿灯/过渡期间有请求被忽略，最大绿灯可能引入强制切换。
   原规则对所有方法一致，不是公平奖励专有优势。当前实验保留公共规则，
   不偷偷添加强制服务。若做动作掩码，需要同步修改探索、行为选择和 Bellman 目标，
   不能仅在测试时修正动作。
4. 首轮没有逐回合保存分项奖励；不能仅凭最终策略的奖励触发率推断训练信号不足。
   新版本补充训练期分项成本、触发率和交通指标的 CSV/TensorBoard 记录。

使用的是 Stable-Baselines3 的标准 DQN，当前没有 Double/Dueling/PER 扩展。
框架说明核对 [官方 DQN 文档](https://stable-baselines3.readthedocs.io/en/master/modules/dqn.html)。
不在此次实验中同时更换学习内核，以免无法判断奖励和状态各自的作用。
交通奖励与状态对齐也可参见 [PressLight 原论文](https://faculty.ist.psu.edu/jessieli/Publications/2019-KDD-presslight.pdf)；
本项目的新奖励是下述可核查的课程设计，不将其冒充 PressLight 的压力奖励或全新理论。

## 两个独立改进

`dqn_dense` 保留原增强 38 维状态，只替换公平成本：

```text
Q = 进口停车车辆数 / 80
H_dense = sum_{本秒全路网停车车辆 i} (2*w_i - 1) / (2*90*80)
r = -Q - 0.3 * H_dense
```

w_i 为本秒停车累计时间加一后的全程停车时间，停车车辆因此有 w_i>=1。
每停车一秒收费等于 w_i²/(2*90*80) 的精确增量；移动时为零，
抵达时不会产生“潜能下降”的额外正奖励。覆盖所有停车车辆，包括队列后方和内部车道。
这是改变优化目标的非负凸等待成本，不是保证保留原最优策略的 potential shaping。
它持续关注等待，倾向于减少等待集中在少数车辆上的情况，但不保证改善任何给定分位数。
无折扣逐秒累加可望远镜求和为终点平方和；实际 DQN 对每个至多 5 秒的平均奖励
使用 gamma=0.99 折扣，仍然是在优化代理目标，而非精确最小化全程平方和或 P95。
归一化使用原有 90 秒实验尺度，lambda=0.3 预先固定：等待约 90 秒的车辆
每秒额外收费约为一个排队车辆基础费用的 30%。新旧 H 定义和单位不同，
不能直接比较 lambda 数值或跨奖励的累计回报。

`dqn_dense_state` 使用同样的密集奖励，换为 44 维状态：当前相位 4、目标相位 4、
green/yellow/all_red 3、阶段计时 1、车道数量/队列 16、车道停车最大累计等待 8、请求年龄 8。
等待和请求年龄使用 w/(w+180) 的有界单调变换，避免 180 秒后硬裁剪。
这是状态改进包，不把整包差异归因于某一个特征；仍是交通局部观测近似。

## 运行前固定的实验

配置为 `configs/improvement.yaml`。5 个学习方法：普通 DQN、等待状态 DQN、
原公平 DQN（先前验证选出的 lambda=1）、密集公平 DQN、密集公平+新状态。
每种方法从头训练种子 11/22/33、每个 50000 决策步，共 15 个模型。
全部使用相同算法超参数、3600 秒需求和最多 1800 秒清空。
MLP 都为 128×128；输入维度导致参数量略有不同，模型记录会披露。

传统基线使用之前验证选出的固定参数，不重新扩大调参范围。
三个场景 × 五条验证车流 1001–1005，每个模型 15 回合，共 225 学习评估回合，
另有 45 传统评估回合。只用开发验证集；不生成或评估预留最终测试车流。
权重不按这轮表现重选，不丢弃最差种子，不挑选最好检查点，仅评估预算末端模型。

评价仍保留平均等待、回合 P95、超 90 秒比例、方向等待、队列、
未完成/未插入、碰撞/传送与强制切换。任何不完整模型/场景不输出性能均值。
先在模型内平均 15 条匹配路线，再比较三个训练种子的均值和样本标准差。
3 个种子只能做小规模描述性重复，不声称统计显著或保证泛化。

```bash
bash scripts/run.sh python scripts/improvement_study.py run --workers 3
bash scripts/run.sh python scripts/summarize_validation.py --run outputs/improvement-50k \
  --destination docs/results/improvement-50k
bash scripts/run.sh python scripts/improvement_study.py summarize
bash scripts/run.sh tensorboard --logdir outputs/improvement-50k/models --host 127.0.0.1
```

三个工作进程各负责一个训练种子；每个进程 PyTorch 单线程，输出目录分开。
先检查纯函数与真实仿真，再提交固定实现和配置，随后开始训练。
本轮模型、原始文件和日志留在 `outputs/improvement-50k/`。
分项奖励训练日志为决策步均值（包括清空阶段），不是只统计固定需求窗口的秒均值；
末端不足 5 秒的决策也按一次决策计入。跨定义比较时应使用原始交通指标。

## 首批三种子实际结果

15 个模型合计 750000 决策步，全部完成训练与保存/重载检查。
三进程训练与验证墙钟用时 1094.23 秒（18.24 分钟）；各模型纯训练耗时相加
为 2708.02 秒（45.13 分钟），两种时间不能混为一谈。
270/270 验证回合全部清空，未完成、未插入、碰撞、传送计数均为零。

以下先在每个模型内平均 15 条车流，再汇总三个训练种子，± 为训练种子的样本标准差。
传统方法没有训练重复，不提供训练标准差。均为开发验证，非最终测试。

| 方法 | 平均等待 s | 平均回合 P95 s | 超 90 秒比例 |
| --- | ---: | ---: | ---: |
| 感应式 | 13.75 | 46.99 | 1.195% |
| aging | 15.41 | 41.24 | 0.000% |
| 普通 DQN | 14.90±0.95 | 56.31±4.23 | 1.842%±0.491% |
| 等待状态 DQN | 15.21±0.68 | 56.60±5.37 | 1.675%±0.395% |
| 原公平 DQN | 15.04±0.46 | 54.95±2.44 | 0.961%±0.426% |
| 连续公平 DQN | 15.36±0.92 | 58.23±9.25 | 1.604%±0.926% |
| 连续公平＋完整状态 | 15.11±0.49 | 54.80±4.04 | 1.248%±0.505% |

原公平 DQN 相对普通 DQN 的模型级均值：平均等待增加 0.134 秒，P95 降低 1.366 秒，
超时比例降低 0.881 个百分点（约 47.8% 相对降幅）。原先种子 11 的排序不能代表稳定排名；
种子 22/33 的 P95 排序相反。样本少，不能据此宣称显著优势。

连续奖励单独替换没有带来改善，尤其种子 11 的 P95 为 68.81 秒，不能丢弃这个种子。
在连续奖励上增加完整状态后，P95 均值降低 3.43 秒，但仍与原公平策略接近，
超 90 秒比例也更高，尚不值得直接替代原方案。

最后十个完整训练回合中，原公平模型的加权公平成本/排队成本比例约为 1.90%，
连续公平模型约为 7.70%，完整状态连续模型约为 7.06%；相应公平成本非零的决策比例
约为 5.96%、97.21%、97.19%。这些数值先按记录的决策步数加权，再跨模型等权平均，
不包含训练结束时未完成的最后一段回合。
可以确认连续奖励确实更稠密、贡献更大，但稠密并不自动等于更好的策略。

首批完整结果保存在 [results/improvement-50k](results/improvement-50k/report.md)，
逐种子结果与对照差异见该目录的 global_per_model.csv、global_summary.csv、
paired_by_seed.csv 和 training_reward_diagnostics.csv。

## 补充对照：原奖励＋完整状态

首批结果出来后，增加一个独立开发试验：保持原公平奖励与 lambda=1.0，
只使用 44 维完整状态。仍为三个种子 11/22/33、每个 50000 步、15 条同一验证车流。
不改学习内核、信号规则、预算或权重，不继续搜索权重和最好检查点。
此对照与已有三组构成“原/连续奖励 × 原/完整状态”的四格实验。
它属于看过开发结果后的后续诊断，不能被包装成预先声明的最终盲测。
