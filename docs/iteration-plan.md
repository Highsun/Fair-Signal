# 迭代实验预先方案

在生成新开发车流、训练新模型及开启预留测试之前冻结本方案。
历史单路口、两路口与修正控制源码不修改；新模块位于 `fair_signal/iteration/`。

## 问题与实验矩阵

1. 泛化：复用普通/公平修正DQN各3个既有模型，比较感应式、压力、Aging。
   新开发种子3001/3002；三个原场景，各需求倍率0.8/1.0/1.2（相对validation原需求）。
   另在正常需求下将下游减速窗口移动至[300,900)及[900,1500)，共22条新开发车流。
   按车流/场景组报告；移动窗口与需求倍率分开统计，不让额外瓶颈案例改变全场景权重。
2. 奖励对齐：两个固定配置，首次累计停车等待>90秒惩罚权重30或90，持续超时权重0.25。
   奖励为负的周期平均 `(stopped+pending + 0.25*excess_stopped + K*first_crossings)/160`。
   增加仅持续超时权重0.25、首次惩罚为0的配对对照，分离减小权重与新增事件惩罚的作用。
   首次事件按真实车辆全程累计等待计数一次，不按连续停车段重复计数。
   K的单位为等价停车秒；只比较这两个预定配置，不根据结果追加扫描。
3. 信息消融：配对的full/local加性Q头，两个头各162→128→128→3，联合Q=Qa+Qb。
   full两个头均见完整观测；local每头仅保留本路口76维及其5维修正信息，其他输入置零。
   结构/参数量/训练预算一致，联合动作仍9个、同一全局奖励。它不是独立多智能体训练。
   本地出口/连接道路状态仍保留，只屏蔽另一节点观测及其基线建议，不声称完全无邻接信息。
   禁止用既有MLP和新local的差异单独归因于协同。

五个新增配置×三个训练种子11/22/33，每模型50000决策步，固定终点，无挑选检查点。
训练车流分布、算法超参数、物理约束与共享服务护栏保持不变。训练与开发/测试车流种子分离。
全部7个学习配置（旧2+新5）与3个规则控制器
在同一开发车流上比较：每条车流24个控制器实例，共528个开发回合。

## 评价与停止规则

主公平指标：超90秒车辆比例；效率：平均停车等待、含插入延迟完整行程。
同时记录P95、每车平均超时部分、主/支路等待、停车次数、未完成与异常事件。
完整回合以TripInfo核对首次超时事件数、停车积分和持续超时积分；审计真实信号轨迹与修正预算。
任一方法在某统计组有未完成回合，保留失败，不报告仅存活回合的整体性能排名。
等权先平均车流，再平均场景，最后平均模型种子；误差条为种子均值样本标准差，非置信区间。
只有3个模型种子，不声称统计显著。

开发集上公平配置的可接受条件：完整、超90秒比例低于普通修正DQN，且平均等待及完整行程
各不超过普通版本的105%。若两者均满足，优先超时比例较低者，平手选K=30。
若均不满足，记录“无可接受公平改进”，不强行推广。选择跨全部3个种子的配置，不挑种子。
评价需求倍率时对三个场景等权；上述选择只用正常需求、标准窗口的新开发集。
消融无胜负选择；直接报告配对full-local差异及每个种子。

完成上述开发、冻结选择记录后，开启原预留4001–4010测试（原test需求倍率1.12，标准窗口）。
在3场景×10条车流上评价全部预定配置，包括未被选择的公平配置作为预定对照，共720回合。
测试集不选超参数/检查点/种子，不因负结果追加修改；最终主策略仍为既有普通修正DQN。
原单路口的历史测试不变；本轮开启的是两路口预留测试。
